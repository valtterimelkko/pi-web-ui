## What was built

**Server side (worktree, commit `c2d527ce`):**
- `scripts/generate-client-snapshot.ts` — deterministic generator deriving the
  client contract from server source: zod-introspected request schemas
  (`createSessionBodySchema`, `sessionControlBodySchema`, `goalSpecSchema`,
  `retentionSchema`, `preflightSpecSchema`), TS-compiler-extracted interfaces
  and aliases (54 types incl. `RunReceipt`, `WatchesWaitResponse`,
  `SessionGoalProjection`, `SendPromptRequest`, …), the 16-route client route
  table (each entry anchored to its handler name), the error-code table, and
  `INTERNAL_API_CONTRACT_VERSION`.
- `docs/contract/internal-api-client-snapshot.json` — the committed snapshot
  (58 KB, 16 routes, 54 types, contract 1.57.0). No timestamps or git metadata:
  regeneration is byte-for-byte reproducible.
- `server/tests/unit/internal-api/client-snapshot-drift.test.ts` — regenerates
  and compares; a server schema/type change without regeneration fails CI.
  Also anchors every route to a living handler and pins the version + codes.
- Doc section in `docs/INTERNAL-API-ORCHESTRATION.md` pointing parents at the
  client and documenting the drift guard. No wire-visible change (snapshot is a
  committed artefact, not a route) — contract stays 1.57.0.

**Client (`/root/pi-orch`, commits `260b2c5`, `56065fe`, `dd502b4`, `0879831`,
`04f3290`, `e5ec95f`):** TypeScript, Node ≥ 22.18 (runs TS directly via type
stripping), **zero runtime dependencies** (`node:http` only). Importable module
(`src/index.ts`) + CLI (`bin/pi-orch`).

- Verbs: `spawn` (route tuple, durable retention, goal, C4 preflight, always
  sends `X-Parent-Session`; `followUpOnBusy` single retry for the create-time
  goal race), `prompt` (detached + idempotency key → runId), `wait`
  (watch-based, never polls: one long-poll on `/watches/wait`, cursor advance,
  slice-boundary receipt reconciliation bounded by long-poll returns, restart
  survival via `fireIfSettled` re-register, distinct outcomes incl.
  `interruptedByRestart` / `NEVER_STARTED` / `RUN_BUDGET_EXCEEDED` /
  `RUN_TRANSPORT_LOST`; goal-armed children wait on `goal_end`+`goal_state`
  matched on the exact objective, deliberately **no per-turn `agent_end`**),
  `result` (finalText + evidence pointers), `verify` (stub for C3, exit 13),
  `cleanup` (release_retention then DELETE), `status` (`?parent=` + goal + last
  receipt), plus read-only `capabilities`/`capacity`/`models`.
- Correction 01 additions: `wait` **fails fast** before registering any watch —
  unknown/malformed `--run-id` (404 `RUN_NOT_FOUND`) or a session missing from
  the registry returns immediately with exit **16**; an already-terminal receipt
  returns its outcome immediately. `wait --all|--any <sessionId>[@<runId>] …`
  waits several children in ONE call (one long-poll over all watches, per-child
  fast-fail, per-child outcomes). `spawn`/`prompt` `--id-only` prints the bare
  id for `$(…)` capture; help + README tell models to use `--json`/`--id-only`
  and never parse human output. 429/503 honoured with a bounded Retry-After
  budget; documented 16-code exit table kept in sync with the README by test.
- Snapshot resolution: `PI_ORCH_SNAPSHOT_PATH` → server main checkout → bundled
  copy; at runtime the client compares the snapshot's `contractVersion` with
  live `/capabilities` and flags a stale snapshot. Builders' own bounds are
  cross-checked against the real snapshot by `ZodSpec` conformance tests.

## Design decisions

- Snapshot over two layers (zod introspection + syntactic TS extraction)
  rather than a runtime dependency: deterministic, committed, CI-enforced; the
  client stays dependency-free and tolerant of additive server fields.
- `wait` reconciles the receipt at slice boundaries (bounded by long-poll
  returns, asserted by test) so receipt-only terminals (NEVER_STARTED,
  RUN_TRANSPORT_LOST, cancelled) surface without polling.
- Goal-armed waits use goal conditions only (goals.md); the per-turn
  `agent_end` variant was tried and ended waits at the goal-start boundary.
- Exit 16 covers both unknown-run and unknown-session fast-fails (one
  "nothing to wait on" code; the JSON names which).
- `/root/pi-orch` stays remote-less; typecheck uses the host TypeScript
  (documented in README) so the repo installs nothing.

## Residual risks

- The snapshot's TS-type layer is syntactic: template-literal types print as
  source text; a type-only change that preserves printed text would not drift
  the snapshot (zod layer + handler anchors cover the request side).
- `wait --any` returns the first settled child; other children keep running
  and are the caller's to reap (documented).
- The parent's brief dispatch may queue behind goal-engine turns; the route
  check therefore counts every executed parent receipt, not just the brief run.
- Live model runs stay small (≤ 6 concurrent children, short prompts, thinking
  low) but are real GLM calls; behaviour under provider congestion was not
  exercised.

## Correction 04 (final implementer round — Luna majors + parent pre-review)

All ten findings fixed RED-first in `/root/pi-orch`; tests 88/88, tsc clean; commits
`78cb648`, `d441752` (+ `04f3290`, `e5ec95f` from earlier rounds).

1. **goal_end is not success** — a `goal_end` firing now reads the live
   projection (`GET /sessions/:id/goal`) and classifies: `achieved` →
   `goal_achieved` (0), `failed` → `goal_failed` (4, reason surfaced),
   `cleared` → `goal_cleared` (17, new), `paused` → `paused` with the reason.
   An unreadable projection is never reported as success. Tests cover failed
   and cleared goals; the live proof shows the classification line.
2. **Question sentinel** — text firings are classified by the REGISTERED
   condition id (normalized text firings carry the underlying event type, e.g.
   `message_update`); test uses a realistic `message_update` firing.
3. **No duplicate children** — a transport failure (lost connection/response)
   no longer retries non-idempotent requests: only safe methods, keyed
   dispatches (`_idempotent`), and 429/503 refusals retry. A lost create
   surfaces `CREATE_UNKNOWN` (exit 18) with `{outcome:"unknown", hint}` telling
   the caller to reconcile with `status --parent` — never to blindly re-spawn.
   Probe test: the dropped-response create produces exactly ONE POST.
4. **Receipt/session mismatch** — wait/waitMany preflight fails fast (exit 16)
   when a receipt's `sessionId` differs from the requested session.
5. **Watch reuse** — an active watch is reused only when its conditions are
   semantically compatible; a watch with the client's own label is replaced; a
   foreign watch yields `WATCH_CONFLICT` (exit 19) — never a silent run to the
   deadline. Probe tests cover foreign, own-label and legacy shapes.
6. **status shape** — `status --parent` enriches every child with busy, goal
   state and last receipt (bounded parallelism 4); direct `status <id>` derives
   busy from session detail. Asserted in tests; shown in the live output.
7. **Snapshot staleness** — implemented: after a successful API verb the CLI
   compares the snapshot's `contractVersion` with live `/capabilities`,
   warns `SNAPSHOT_STALE` on stderr and flags JSON output
   (`snapshot: {stale, snapshotVersion, serverVersion}`) without blocking.
8. **Retry-After** — the delay is waited in full; a delay the remaining budget
   cannot cover returns the refusal with its retry hint instead of retrying
   early. Tests cover both.
9. **P1 `npm test`** — fixed for Node 24 (glob form); `npm test` → exit 0.
10. **P2 raw evidence** — the real-parent proof copies the parent's and every
   child's session JSONL into `c1/live/evidence/` (token-like strings redacted
   on write; the strict key-pattern scan of the preserved files is clean) and
   the curl/sleep counter runs on the PRESERVED parent transcript.
