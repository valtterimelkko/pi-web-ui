## 2. Disposable topology (mirrors production, scaled down)

`e2a-3.slice` (runtime drop-in: `MemoryMax=12G`, `MemorySwapMax=1G`, always (re)applied and read back)
→ `e2a-3-tools-anchor.service` (production anchor pattern: `Delegate=cpu memory pids`, `DelegateSubgroup=supervisor`, `OOMPolicy=continue`, `ExitType=cgroup`, `OOMScoreAdjust=-1000`, `Restart=always`, ExecStart re-enables `+cpu +memory +pids` in its own subtree)
→ `e2a-3-server.service` (the worktree build via the disposable validation-server entrypoint, `--compiled`, isolated socket/token/state, fake `$HOME`, isolated agent dir, placement env via the wrapper's `--env-file` mechanism; `UnsetEnvironment` strips production's `PI_TOOLS_*`).

Boot asserts, by script, that the server's placement line is `tools root verified …/e2a-3-tools-anchor.service` — a `DISABLED` line or production's anchor fails the boot.

Two production-topology facts the harness had to mirror correctly (both proven on live disposable units during the smoke round):

- systemd derives a slice's parent from its name: `e2a-3.slice` lands at `/e2a.slice/e2a-3.slice/…`, so cgroup paths are resolved via `systemctl show -p ControlGroup`, never assumed.
- `systemd-run` in systemd 255 ignores `--property=ExecStart=…` without a positional command, and the disposable wrapper parses only space-separated flags (`--port 1234`, not `--port=1234`).
