## 1. What was built

- **`server/src/pi/sdk-extension-importer.ts`** (new): imports extension
  factories with **jiti 2.7.0** (direct dep added to `server/package.json` by
  the parent, commit `d0a5d1fa`) and an alias map that replicates the SDK's
  private `getAliases()` through public resolution only — SDK package scope,
  nested-first companion resolution (`pi-tui` exists only nested), exports-map
  `import`-condition reads with wildcard support and legacy-`main` fallback,
  `typebox` via `createRequire(sdkEntry).resolve` exactly as the SDK does,
  realpathed targets. Verified boundary fact: `loadExtensionFromFactory` is
  **not** exported from the package entry in pristine 0.87.1 — and is not
  needed; the loader's `extensionFactories` option makes the SDK call it
  internally.
- **`server/src/pi/extension-factory-cache.ts`**: seeding deleted; `load()`
  hands ordered factories to the new `createExtensionFactoryResourceLoader()`,
  which builds each session loader with the public `extensionFactories` +
  `noExtensions` + `additionalExtensionPaths` (resolve() enabled order minus
  cached globals, per-loader `SettingsManager`) and restores real paths, order
  and error labels in `extensionsOverride` before the loader recomputes every
  `sourceInfo`. A factory wrapper dereferences the cache's **current** factory
  at init time, so `/reload` picks up cached-extension code changes. The
  allowlist (15/16), whole-tree fingerprint freshness, bounded scan, symlink
  refusal and the critical section are unchanged.
- **Graceful degradation (parent requirement)**: SDK version outside the
  validated `0.87.x` range, unresolvable alias target, jiti import failure,
  frozen/changed result objects, and parity self-check mismatch each degrade
  **that session** to the plain uncached SDK loader (full correct extension
  set), with one rate-limited warning and the bounded counter
  `getExtensionLoaderTelemetry()`. A systemic importer failure (every allowlisted
  import failed) also trips the fallback; one broken extension does not (it
  stays uncached and the loader reports it — today's behaviour). Documented in
  `docs/OBSERVABILITY.md` ("Extension-factory degradation (B1.2b)") and
  `docs/ARCHITECTURE.md`.
- **`server/src/pi/pi-service.ts`**: per-session loaders go through the
  factory-backed builder inside the existing critical section;
  `reloadSession` refreshes the factory cache before `session.reload()`. The
  boot-time loader stays the plain constructor loader (deviation from
  `01-design.md` §2, which proposed replacing it: the boot reload is a one-off
  full import either way, and replacing it would create a second
  `process.cwd()` loader, breaking the tested invariant that only the boot
  placeholder uses `process.cwd()`; the factory path is exercised by every
  session open).
- **Deletions**: `scripts/patch-pi-coding-agent-extension-factory.mjs`, its
  root `postinstall` chain entry (pi-ai toolstream entry untouched), and
  `server/tests/unit/pi/extension-factory-patch-regression.test.ts`
  (replaced by the pristine-SDK suite).

## 8. Residual risks

- The `extensionsOverride` parity rewrite mutates public result fields
  (`path`, `resolvedPath`, `errors[].path`) and array order; an SDK change that
  freezes or reshapes them fails loudly (parity self-check → session degrades
  to the plain loader, warning + counter) and the CI version pin forces
  re-validation on bumps.
- `/reload` on an already-open session does not pick up newly added/removed
  extension files until that session's next open (accepted by the parent;
  documented in `docs/ARCHITECTURE.md`). Code changes DO reload.
- The alias map is version-coupled to the SDK 0.87.x line and to this node_modules
  layout (nested companions); both are fail-loud in CI and fail-safe at runtime.
- The +20% steady-state per-open cost and the first-window warm-up outlier
  (§4); if production shows the outlier repeatedly across restarts, the B2 gate
  as proposed (sustained two readings) still does not trip.

## 9. Correction 02 (independent review + parent adjudication, 2026-09-29)

`reviews/b1-2b-luna-review.md` returned REJECT (1 major, 3 minors); the parent
accepted all findings (`02-correction.md`). Fixed in commit `38b14c2e`; every
fix written test-first.

1. **[major] `/reload` must not depend on the mutable process cache — fixed.**
   Each loader now captures its own `path → factory` snapshot at construction;
   the `extensionFactories` wrappers read ONLY that snapshot. The process cache
   can prune or clear freely without touching an open session.
   `refreshExtensionFactories(agentDir, { snapshot })` updates EXACTLY the given
   session's snapshot, atomically and only with successful imports; snapshot
   ownership lives in `PiService` (`sessionFactorySnapshots`, released in
   `releaseSessionRefs`). Semantics, each test-proven:
   - removed extension → snapshot kept, `/reload` succeeds, extension still loaded;
   - over-budget scan → snapshot untouched, `/reload` succeeds;
   - failed re-import of a changed extension → the snapshot entry is marked
     `failed` and the reload surfaces that extension's load error with its real
     path (absent from `extensions`, present in `errors`) — SDK parity, no
     stale code; the process cache also drops the stale entry so the next open
     re-attempts the import;
   - session A's reload never changes session B's snapshot or loaded state.
   The builder's systemic-failure check is unchanged; a path that failed to
   import at construction is simply not a factory (it stays in
   `additionalExtensionPaths` and the loader reports it per session).
2. **[minor] runtime version guard exact — fixed.** `resolveSdkAliasMap`
   compares against `VALIDATED_SDK_VERSION` (`0.87.1`) exactly; any other
   version — including same-minor bumps like `0.87.2` — degrades to the plain
   uncached path. The CI pin test stays.
3. **[minor] diagnostics parity — fixed, one documented residual.** The parity
   pass rewrites `<inline:…>` in error paths AND in embedded message text
   (conflict diagnostics name the conflicting owner path in the message), and
   the parity self-check tolerates an errored extension exactly as the
   discovered path would. The parity projection now includes `errors`, and the
   conflict test (two cached extensions registering the same tool and command)
   asserts full projection equality plus no `<inline:` anywhere in the result.
   Residual (documented, not fixable through the public API): conflict
   DETECTION runs inside the loader before the override, so a conflict's owner
   and order reflect load order, not the restored extension order — visible
   only when an uncached and a cached extension collide on the same name.
4. **[minor] warning flood — fixed.** Importer failures aggregate into ONE
   rate-limited warning per scan (bounded path list, 5 s window, same class as
   `noteFallback`); the per-extension per-load warning is gone. Test: a
   globally broken importer across 5 loads emits at most one import-failure
   warning.

Also fixed per the review's housekeeping: dead `peekFactory` removed (wrappers
read snapshots), the orphaned docblock after it removed, trailing blank lines
at EOF in `sdk-extension-importer.ts` removed (`git diff --check` clean), and
the importer's failure wrap now embeds the underlying error message so
per-session load errors carry the same diagnostic text as the uncached path.
