## 7. Blind spots (what this mechanism does NOT see or cover)

- **Untracked files (parent question, 01-answer addition 1):** an untracked file under a source root never changes the guard's answer — both the staleness diff (`git diff` sees committed trees only) and the dirty check (`--untracked-files=no`, hb4 behaviour) ignore untracked files. An untracked file **added after the build** is irrelevant to built content; an untracked file **present at build time** would have fed the manifest's `sourceFingerprint` (build-time digests read the working tree directly) while the guard compares git content only — so the guard's allow is a statement about HEAD, not about every byte the build read. **This is exactly today's (hb4) behaviour**: the old revision-equality guard also allowed whenever `manifest.rev == HEAD` regardless of untracked build-time files. No new hole is introduced by J1; if the parent wants build-time untracked source under a source root to refuse, that is a new hb4-era gap needing its own decision (working-tree fingerprint comparison or an untracked-file scan) — not silently added here.
- **Declared inputs only:** staleness is judged over `BUILD_INPUT_POLICY` paths; a future input added to the policy is covered only when the bash mirror is updated — drift fails the pinning test.
- **Installed tree vs lockfile:** the guard compares lockfile content (git), not `node_modules` state; a drift between them is invisible (unchanged from today).
- **client/dist:** the guard reads only `server/dist`'s build identity; client output staleness is out of scope (unchanged from today).
- **History weirdness:** a manifest revision that exists but sits on a rewritten/foreign history yields a full diff → refuse (fails closed, but the message says "stale" rather than "foreign history").
- **Wrapper coverage:** exit-3 mapping exists in `restart-pi-web-ui.sh`; direct callers of `restart-production.sh` (humans, `with-production-lock.sh` routing) see exit 3 raw — documented in DEPLOYMENT.md.
- **Proof realism:** stub `systemctl` + fake curl; real systemd and real curl `--unix-socket` transport are production behaviour proven by the existing disposable validation paths, not here (same stance as the B4/Hb4 script tests).
