## 7. Blind spots (what this mechanism does NOT see or cover)

- **Untracked files (parent question, 01-answer addition 1):** an untracked file under a source root never changes the guard's answer — both the staleness diff (`git diff` sees committed trees only) and the dirty check (`--untracked-files=no`, hb4 behaviour) ignore untracked files. An untracked file **added after the build** is irrelevant to built content; an untracked file **present at build time** would have fed the manifest's `sourceFingerprint` while the guard compares git content only — so the guard's allow is a statement about HEAD, not about every byte the build read. **Exactly today's (hb4) behaviour**; no new hole introduced by J1. If the owner wants build-time untracked source under a source root to refuse, that is a separate hb4-era gap needing its own decision.
- **Declared inputs only:** staleness is judged over `BUILD_INPUT_POLICY` paths; list drift is caught by the pinning test, not at runtime.
- **Installed tree vs lockfile:** the guard compares lockfile content (git), not `node_modules` state (unchanged from today).
- **client/dist:** out of scope (unchanged from today).
- **History weirdness:** a manifest revision on a rewritten/foreign history yields a full diff → refuse (fails closed; message says "stale" rather than "foreign history").
- **Wrapper coverage:** exit-3 mapping exists in `restart-pi-web-ui.sh`; direct callers of `restart-production.sh` see exit 3 raw — documented in DEPLOYMENT.md.
- **Proof realism:** stub `systemctl` + fake curl; real systemd and real curl transport are production behaviour proven elsewhere (same stance as the B4/Hb4 script tests).
- **Correction 02:** the entry-load test pins the npm-script loading context; it does not prove the timer's systemd environment (same tsx invocation via npm, but systemd env vars are the unit's own domain).

## 8. Correction 02 — the weekly refresh under Pi SDK 1.0.0 (`02-correction.md`)

**Finding (this lane's §8 report, reproduced by the parent on master):** `import('./scripts/command-code-weekly-refresh.ts')` in the npm script's context (tsx from the root; root `package.json` declares no `"type"`) failed with `ERR_PACKAGE_PATH_NOT_EXPORTED` for `@earendil-works/pi-coding-agent` 1.0.0 (exports map: `.` only under `import`/`types`). Chain: `command-code-model-catalog.ts` → `../placement/index.js` → `placement/bash-tool.ts` → value import `createBashToolDefinition`.

**Fix (scripts/package.json side only — no server/src change, so nothing needed `03-question.md`; no upstream change):**
- `scripts/command-code-weekly-refresh.ts` → **`scripts/command-code-weekly-refresh.mts`** (git mv): `.mts` pins the entry to ESM regardless of the root package's implicit CJS, so the whole import graph loads via `import` and the upstream ESM-only export resolves.
- Root `package.json`: `"commandcode:weekly-refresh": "tsx scripts/command-code-weekly-refresh.mts"`; the systemd timer runs the same npm script, so its behaviour follows automatically.
- Lint plumbing (mechanical consequence of the rename, disclosed): `.eslintrc.json` scripts override now includes `scripts/**/*.mts` (restores the job's pre-rename `no-console`-off posture), and the `lint` script's explicit second eslint list now names the job file — without this the renamed entry silently dropped out of `npm run lint` and lint:ratchet read `329 > 326`. Deviation note: the correction owned "package.json (the scripts entry for this job only)"; the `lint` script amendment is a second entry, made because the rename otherwise regressed lint coverage — reversible independently if the parent disagrees.
- Permanent tripwire: `server/tests/unit/command-code/command-code-weekly-refresh-entry-load.test.ts` loads the entry exactly as the npm script does (tsx from the repo root, repo-relative paths, CI-portable/unprivileged) and asserts a clean import with the expected exports. Importing never executes the job: the entry's main-module guard (`invokedPath === path.resolve(fileURLToPath(import.meta.url))`) is false under `tsx -e` (unset `process.argv[1]`) — stated in the test.
