## What shipped

- **Pi busy-session accessor (narrow, read-only, new method only).** `MultiSessionManager.listBusySessions()` (`server/src/pi/multi-session-manager.ts`) returns payload-free `PiBusySession { sessionId, sessionPath, busyBecause }` for every resident session the manager's status flag (`busy`/`streaming`) or the SDK's public `AgentSession.isStreaming` state reports busy. No dispose/unload path touched (lane b5's). A throwing getter is swallowed (not busy evidence).
- **Drain busy seam.** `DrainController` gains `listBusySessions` (optional dep). `measure()` counts them into `remaining.busySessions`/`remaining.sessions`; the settle condition now also requires zero busy sessions — a goal-engine continuation, another extension-driven turn or a browser (P0) turn keeps the drain open exactly like a run. A timed-out drain lists `cutOffSessionIds` in the verdict and `cutOffSessions` (payload-free refs with `busyReason`, e.g. `sdk_streaming`, `status`, `status+sdk_streaming`, `runtime-running`) in the **v2 durable record** (reader accepts v1 and v2). `initial.busySessions` and `lastOutcome.cutOffSessionIds` added. A failing accessor degrades fail-open with a warning — parity with the receipt source.
- **Cross-runtime wiring** (`server/src/internal-api/server.ts`): Pi via the accessor; other runtimes via their **existing** busy flags (`claudeService/opencodeService/antigravityService/commandCodeService.isRunning`) over a registry snapshot refreshed at boot, awaited before every drain start (`createDrainRoutes` `onBeforeStart` hook; a rejection never blocks the drain) and on every measure. Snapshot entries are `{id, sdkType}` only.
- **Boot reconciliation for receipt-less cut-off sessions.** From the consumed drain record's `cutOffSessions`, every session with **no** recovered run receipt fires the ordinary interruption path (`WatchManager.reconcileRestartInterruptions`): one synthetic `agent_end`, plus `goal_end` when pending, with `data: {interruptedByRestart: true, status: 'interrupted', runId: 'busy-<sessionId>', busySession: true, errorCode: 'SERVER_RESTART', interruptionReason: 'drain_timeout'}` — `runId` carries the SYNTHETIC interruption reference, `runIds` is absent. Sessions that also have receipts reconcile from the receipts only (one firing per session). A failing busy source never blocks the receipt reconciliation. Wake suffix keeps the B4 form: `(interrupted by restart: run busy-<sessionId>, drain_timeout)`.
- **Contract 1.52.0** (additive) with changelog entry, drain section of `docs/INTERNAL-API.md` rewritten, version pins updated. `DEPLOYMENT.md` unchanged (deploy script semantics did not change — see Not done).

## Design decisions

- **Busy sessions block the settle wait exactly like runs; no origin special-casing.** The plan's approach sentence counts browser turns in the settle wait; a human's interactive turn is the same harm class as an orchestration child (the owner's "ready" is "children are not killed by deploys"); and the configured timeout already bounds the wait, so a long interactive turn delays a deploy by at most `timeoutSeconds`. The `remaining.sessions` refs make visible WHY a drain is waiting — previously this work was invisible.
- **Synthetic interruption reference `busy-<sessionId>`, carried in `data.runId`, with `data.busySession: true`.** One wake-suffix format for parents (B4 correction 01 finding 4 invariant preserved); the flag lets a parent tell it from a receipt-backed run; `runIds` is absent (no runs exist).
- **Receipts win at boot.** A session listed in both `cutOffRunIds` and `cutOffSessions` reconciles once from its receipts — the busy entry is skipped. Live-proven by the control child.
- **Sync accessors over an async registry.** The drain's measure path is synchronous (interval-driven state machine); the cross-runtime registry list is async. server.ts keeps a minimal snapshot (`{id, sdkType}`), refreshed at boot, **awaited before every drain start** (`onBeforeStart`), and re-refreshed per measure (fire-and-forget, ≤1 poll of staleness mid-drain). Pi — the owner's primary runtime — is always read live, never from the snapshot.
- **Fail-open on accessor errors** (warn + treat as none), parity with B4's receipt-source behaviour; a broken source must not stall deploys forever. The warning keeps the blind spot visible.
- **DrainRecord v2** with `cutOffSessions`; the reader accepts v1 (empty list) and v2, validating/dropping malformed entries — a 1.51.0 build reading a leftover v2 record logs, ignores it, and classifies plainly.

## Residual risks / blind spots (for §1.1 adjudication)

- **Unplanned restarts (crash, OOM, `--force`) still cannot announce receipt-less busy sessions at boot** — there is no record of what was in flight. This is B4's pre-existing blind spot, not widened or narrowed by B4.1.
- **Non-Pi busy enumeration depends on the registry snapshot**: a turn started on a non-Pi runtime within the snapshot's staleness window before drain start can be missed at the first measure; mid-drain it is caught at the next ≤500 ms poll. Pi is exempt (always live).
- **A stuck-busy session holds the drain to the timeout** (e.g. stale-streaming before the manager's 15-min reset) — same semantics as a stuck receipt; bounded by `timeoutSeconds`.
- **The drain cannot say WHO started a busy turn** (goal-engine vs browser vs subagent) — deliberate: same harm class, and `busyBecause` keeps the reference payload-free.
- **Rollback**: a v2 drain record on a pre-1.52.0 build is read as malformed (logged, ignored); boot classification falls back to plain `server_restart` for runs, and receipt-less busy sessions are simply unknown to it (as before).
