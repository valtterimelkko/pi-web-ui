## The incident, plainly

- **Cause:** the arm-B fixture step invoked `npm ci` through a helper that passed no working directory, so it inherited the driver's cwd — the lane worktree root, whose `node_modules` was a **symlink into production** (`/root/pi-web-ui/node_modules`). npm's reify followed the symlink.
- **Impact:** production's `node_modules` was **empty from 06:01Z to 06:44Z** (all 621 packages gone). The running server stayed healthy the whole time (its modules were already in memory; `/health` ok; MainPID 3717595 unchanged) — but a restart in that window would have failed to boot. No restart occurred; nothing else on the host consumed a not-yet-loaded module in the window.
- **Restoration:** the parent ran `npm ci` in the main checkout at 06:44Z (lockfile intact and identical to deployed build `dc9a32a6`); 621 packages back including devDependencies, native modules (`better-sqlite3`, `bcrypt`, `node-pty`) rebuilt and loading; this worktree's stray real `node_modules` was removed and the symlink restored by the parent.
- **Fix (RED→GREEN):** `assertSafeNpmCwd` (`scripts/e2a-fanout/lib/fixtures.ts`) refuses any npm invocation whose cwd is not under `/root/e2a-runs/a4/`, whose fixture directory is missing, whose real path escapes the run root, or whose target `node_modules` is a symlink; wired into the fixture step before `npm ci`. Guard test 5/5 written RED first (suite 40/45 → 45/45). `run()` also gained the explicit `{ cwd }` pass-through. Commit `9ac29171` (guard) on top of `bb32e1cb` (cwd plumbing + run-1 evidence fixes).
