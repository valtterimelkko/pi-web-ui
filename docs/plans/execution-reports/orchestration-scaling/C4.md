## What shipped

- **New module** `server/src/internal-api/dispatch-preflight.ts`: deterministic
  preflight for dispatches — effective cwd exists + is a directory + is writable
  by the server user; caller-declared referenced paths exist (existence only);
  caller-declared bare tool names resolve to executable regular files on the
  server `PATH` (which runtime children inherit). Aggregates every failure (no
  short-circuit); fs and PATH injectable for tests; no child processes, no
  provider calls, no reads beyond existence/writability probes.
- **Error code `PREFLIGHT_FAILED`** (400) in `error-codes.ts` with catalog
  metadata (description/cause/hint/docs); the response body adds
  `failures: [{kind: "cwd"|"path"|"tool", item, problem}]`.
- **Schema** (`session-validation.ts`): optional strict `preflight`
  (`{paths?: string[] ≤32 absolute ≤4096 chars, tools?: string[] ≤32 bare
  names}`) on `createSessionBodySchema` and `batchCreateEntrySchema`.
- **Types** (`types.ts`): `preflight` on `CreateSessionRequest`,
  `BatchCreateEntry`, `SendPromptRequest`; `failures[]` on the batch create
  result error; `INTERNAL_API_CONTRACT_VERSION = '1.53.0'` (lane-assigned).
- **Route hooks** (`routes/sessions.ts`):
  - `POST /sessions`: preflight after the admission gate, before any runtime
    work; the effective cwd is **always** checked (default-on), plus declared
    paths/tools. Refusal `400 PREFLIGHT_FAILED` + `failures[]`.
  - `POST /sessions/batch`: per-entry preflight after that entry's admission
    check; only the failing entry fails (partial-success semantics unchanged);
    the item's `error` carries `failures[]`.
  - `POST /sessions/:id/prompt`: optional `preflight` field checked after
    injection screening and mode validation, **before** any receipt, admission
    decision or runtime call. Malformed shape → `400 INVALID_REQUEST`. The
    session cwd is not re-checked.
- **Docs**: `docs/INTERNAL-API.md` (create field row, new "Dispatch preflight
  (contract 1.53.0)" section, prompt field row);
  `docs/INTERNAL-API-CONTRACT.md` (example version 1.53.0 + changelog entry).
- **Test fixtures** aligned with the default-on cwd check and the version bump
  (see "Fixture fallout" below).

## What this mechanism does NOT see or cover (blind spots, per §4 R2 rule)

1. **Point-in-time (TOCTOU).** Probes answer "valid at dispatch time"; state
   can change between the probe and the runtime spawn (or mid-run). Nothing
   here watches the workspace afterwards.
2. **Root semantics.** The server (and runtime children) run as root on this
   host; `access(W_OK)` under `CAP_DAC_OVERRIDE` reports writable even for
   mode-0o555 directories. The check is consistent with what the same-user
   runtime child experiences, but a future non-root deployment would need the
   check re-evaluated.
3. **Paths are existence-only.** A referenced path that exists but is
   unreadable/unwritable passes; no type, permission or content checks.
4. **Tools are name-resolution only.** Resolved on the server's `PATH` at
   check time (children inherit the same env today); a PATH mutation between
   check and spawn is unseen, and a wrong-version tool passes. No `--version`
   probing (deliberate: no execution of caller-named binaries).
5. **Surfaces not in the owned brief are not preflighted:** transfer-created
   sessions (`POST /sessions/:id/transfer` with `createNew`) and
   adopt/adopt-native paths; `POST /sessions/batch/prompt` items have no
   `preflight` field. Existing-session prompt dispatch cannot re-check the
   session cwd (it was validated at create; deletion since is TOCTOU class).
6. **Runtime-specific readiness is out of scope:** auth/credential presence,
   disk space, git state, provider availability. The 43% baseline counts
   workspace problems beyond the three classes checked here.
7. **Non-POSIX paths** are rejected by schema (absolute `/`-rooted required);
   this host is Linux.

## Residual risks

- Callers that deliberately create sessions into not-yet-existing cwds (relying
  on the runtime or later steps to create them) now get `400 PREFLIGHT_FAILED`.
  No first-party caller does this (checked: live-validate, heap-soak driver,
  validation env builder's `workspace` dir is only reached via scenario-explicit
  cwds that live-validate creates), but external Agent OS tooling could. Fix is
  caller-side: create the dir or drop the cwd field (server default exists).
- Batch preflight runs per entry concurrently (≤ 4); a spec whose items fail
  only under concurrency (none known — probes are stat/access only) would race.
- The writability probe cannot distinguish "root can write" from "a non-root
  runtime could write" (blind spot 2); relevant only if the deployment model
  changes.
