## Proven root cause

Both halves of the parent's hypothesis are real, and compounding:

1. **Session-scoped quiescence holds leases against *other* work** — `server/src/internal-api/run-receipts/run-receipt-manager.ts` `terminalize()` (≈:816-830 pre-fix): a `cancelled`/`failed` run with an attached lease and unconfirmed cessation enters `drainAndRelease()` (≈:832-841), which polls **`isRuntimeQuiescent(sessionId)`** — the WHOLE session — every second for 30 s (`drainTimeoutMs`). Production shape, reproduced live: a **watch-wake follow-up** gets its own admission lease in `dispatchWatchWakeReceipted` (`server/src/internal-api/routes/sessions.ts`:1283-1304), is dispatched into a busy session, never receives eligible activity (the running turn is silent), and the start watchdog terminalises it `NEVER_STARTED` (`reconcileStalledRuns`, manager ≈:700-727). Its drain then polls against the **goal-engine continuation turn — which is receipt-less** (the goal extension drives the runtime directly, no Internal API receipt), so quiescence stays false and the lease **quarantines** although the run's own work never started and no non-terminal receipt stands behind it.
2. **Quarantine was terminal** — `quarantine()` (≈:849-857 pre-fix) cleared the poll timer and nothing ever re-checked: the slot was held until restart. Quarantined leases never release, so `AdmissionController.activeTurns` stays inflated (`acquire`/`release`, `admission-controller.ts`:673-701); the memory projection (`evaluatePressure`, ≈:731-733) then counts `(activeTurns+1) × 512 MiB` against the 1.5 GiB floor — with 10 phantom turns that is exactly production's 2026-10-03 snapshot (`projectedHeadroomBytes` 1.34 GiB < `minimumHeadroomBytes` 1.61 GiB → `memory_pressure` with ~19 GiB host free; `e2/debt-evidence-20261003T074450Z/capacity.json`).

Production receipt cross-check (`receipts-since-2213Z.json`): 13 failed steers + failed follow-ups clustered on goal-armed children (01a0fdf4: 13 failed steers against one stale-streaming goal session; failed follow-ups on 01a0ff2e/01a0ffcd/01a0fff8), plus 21 cancelled prompts — the lease-carrying terminal shapes. Steers themselves are joined and lease-less (`routes/sessions.ts`:4028-4062), so they never quarantine (confirmed by the live controls below); the wake-follow-up and cancel/abort paths carry the leases.

## Fix (smallest correct change)

- **Reconciliation guard** (`run-receipt-manager.ts`): `quarantine()` now records `quarantinedAtMs` and arms one shared slow poll (`quarantineReconcileMs`, default 60 s, injected seam). `reconcileQuarantined()` re-checks each quarantined entry and **releases the slot when the run's WHOLE session is confirmed quiescent** (persisting resource-quiescence evidence best-effort; release happens even if the store write fails, so a durable-store hiccup cannot recreate the leak). A busy/streaming session or a throwing lookup keeps the entry held — fail-closed, strictly stronger than "that run's work": a quiescent session cannot still be running that run's work. §11 fence intent preserved; `confirmRuntimeQuiescent` semantics unchanged.
- **`/capacity` observability**: `quarantinedOldestAgeMs` (age of the oldest quarantined entry; absent when none) — `routes/sessions.ts` `handleCapacity`, `internal-api/types.ts` `CapacityResponse`. Contract **1.59.0** (additive minor; R5 owner exception row in `docs/INTERNAL-API-CONTRACT.md`; entries in `docs/INTERNAL-API.md` and the contract changelog; client snapshot regenerated; stability-window baseline re-based with the exception row; version pins updated).

## Correction 01 (2026-10-03, after the Luna r1 review — verdict REJECT, three valid findings)

Review: `/root/orch-ops/orchestration-scaling/reviews/L1-luna-review-r1.md`; correction brief: `/root/orch-ops/orchestration-scaling/k/L1/01-correction.md` (binding). All three findings fixed in one commit, TDD RED first.

### Finding 1 (blocker) — Pi release predicate now includes SDK activity

The guard released on `isRuntimeQuiescent`, whose Pi branch read manager status only (`readPiRuntimeQuiescence`); `{status:'idle', sdkStreaming:true}` (the stale-streaming watchdog's reset, `multi-session-manager.ts:604-605`) read as quiescent while an SDK/browser/goal turn was still streaming.

- **One shared truth:** `runtime-quiescence.ts` gains `isPiSessionQuiescent({status, sdkStreaming, compacting})` (busy = manager busy/streaming OR `sdkStreaming` OR `compacting`); `readPiRuntimeQuiescence` now delegates to it, and `piLiveness` (routes/sessions.ts) computes `busy = !isPiSessionQuiescent(statusInfo)` — one busy predicate shared by dispatch, busy refusals and release decisions. No copy.
- **Drain-path decision:** the 30 s drain window uses the SAME corrected predicate — it shares the wiring's `isRuntimeQuiescent` callback, so both the drain hold and the reconciliation guard see identical truth. Decided: both must share; a false release inside the drain window would be the same defect, sooner.
- **RED test (the correction's named test):** `run-receipt-quarantine-reconciliation.test.ts` "stays quarantined through a stale-streaming reset while the SDK still streams; releases only when streaming ends" — RED (predicate result was true), GREEN after. Plus `runtime-quiescence.test.ts` truth-table tests (idle+sdkStreaming false; compacting false; shared lookup helper).

### Finding 2 (blocker) — a missing session is not proof of cessation

`server.ts` treated `!(await sessionRegistry.get(id))` as quiescent; DELETE aborts Claude/OpenCode/Antigravity without awaiting termination (OpenCode clears `runningSessions` before the remote abort is acknowledged), so a deleted-but-running child released its quarantined slot.

- **Smallest mechanism (no new termination plumbing):** new `run-receipts/deletion-cessation.ts` (`DeletedSessionCessation`). `handleDeleteSession` records `{runtime, terminationAcked}` before the registry entry disappears — Pi (awaited `disposeLoadedSession`) and Command Code (awaited `deleteSession`) record **acked**; Claude/OpenCode/Antigravity record **not acked**. The wiring's missing-entry branch consults the tracker: acked → quiescent; not acked → held for a bounded **15-minute grace** (`DELETION_CESSATION_GRACE_MS`), then released exactly once with a `grace-release` log naming the runtime. Never-observed sessions stay held (fail-closed).
- **RED tests:** `deletion-cessation.test.ts` (acked immediate; non-awaiting held through the grace then exactly-one grace-release log naming the runtime; fail-closed for never-observed; re-delete restarts the grace); manager-wiring test "a DELETE during a quarantined run: Pi releases on the awaited dispose ack; Claude holds through the grace then grace-releases"; route test "DELETE records deletion cessation" (claude recorded not-acked).

### Finding 3 (major) — the reproduction script cleans up its own credentials

`boot.ts stop` now deletes the run's `internal-api-token` **and** the isolated agent-dir's filtered `auth.json`/`models.json`, then walks the whole run directory and **fails if any credential copy remains** (`findCredentialCopies`); `boot.ts verify-clean` re-checks on demand. Scripted check recorded in evidence: simulated filtered copies planted in `l1-r2/agent-dir` (dummy content), `stop` removed both and verified clean (exit 0), `verify-clean` clean on all three run dirs — `k/L1/evidence/stop-cleanup-check.txt`.

## Correction 02 (2026-10-03, FINAL round — after the Luna r2 closure; the parent verifies, no further review)

Review: `/root/orch-ops/orchestration-scaling/reviews/L1-luna-review-r2.md` (r1 findings 1 and 3 CLOSED, 2 PARTLY CLOSED, one new major); correction brief: `/root/orch-ops/orchestration-scaling/k/L1/02-correction.md` (binding, narrow). One commit, TDD RED first.

### A. Deletion ordering (finding 2 remainder)

- **Route order:** `handleDeleteSession` now records the deletion into `DeletedSessionCessation` **before** calling the runtime's `abort()` (moved from after the observer/claim teardown to directly before the abort branches), so the record exists from the earliest moment of the deletion window.
- **Callback order:** the server's quiescence callback is now the exported, test-driven factory `createRuntimeQuiescencePredicate` (`server.ts`) and consults the deletion tracker **first** — `if (tracker.has(sessionId)) return tracker.isQuiescent(sessionId)` — before Command Code / registry / `!service.isRunning()` branches. An abort-only runtime whose `isRunning()` flipped false mid-delete can no longer read as quiescent while its registry entry still exists.
- **RED test through the real ordering:** new `runtime-quiescence-predicate.test.ts` drives the exported factory: an OpenCode DELETE with a quarantined run — registry entry present, `isRunning()` already false, record not acked — stays **not quiescent** through the grace and releases only after it (RED pre-fix: the old ordering returned `!isRunning()` = true). Plus preserved-behaviour (no record → runtime truth), fail-closed missing entry, and pi-recorded-before-ack cases.

### B. Tracker records retire (new major)

`DeletedSessionCessation` records are retired once **no receipt can consult them** (new `hasConsultant` seam; in the wiring: `runReceiptManager.hasDrainingForSession(sessionId)` — new accessor — or any non-terminal run for the session) **and** the required grace has elapsed:

- an **acked** delete with no consultant is retired at once (`record()` no-ops into retirement);
- a **grace-pending** record survives until its release, stays while a consultant remains (a second quarantined run of the same deleted session can never be stranded), and is removed on the first consult after the consultant clears;
- a past-grace record with no consultant retires with its release decision (logged exactly once); retired records fail closed.

**RED tests:** 100 acked deletes with no consultant → 0 retained records (the reviewer's probe shape); acked record kept while a consultant exists then retired when it clears; grace-pending record survives until release then goes; unacked past-grace retires without a second release. Manager accessor test: `hasDrainingForSession` sees draining/quarantined entries and clears on release.

### C. Documented, not in scope

A plain `/abort` on OpenCode clears `isRunning()` before remote cessation is acknowledged. That behaviour predates L1 — the 30-second drain path has always used `!opencodeService.isRunning()` — and OpenCode is disabled in this production (`OPENCODE_ENABLED=false`). **Residual risk:** on an OpenCode-enabled deployment, an aborted (not deleted) session's drain window may confirm cessation early and release its slot while the remote abort is still in flight; fixing it means new termination plumbing, which this lane was told not to build. Recorded here as the residual risk of record.
