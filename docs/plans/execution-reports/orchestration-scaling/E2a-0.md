## What was built

One zero-dependency Node 24 `.mjs` (`guard.mjs`, ~740 lines) plus tests and launchers. Node was chosen over Python because the host runs Node 24 with a first-class `node --test` runner, `node:http` gives Unix-socket HTTP without dependencies, and `fs.statfs` removes the need to shell out for disk free.

| Piece | Where | Notes |
|---|---|---|
| `evaluate(sample, baseline, flags, thresholds, state)` | guard.mjs | pure; returns `{hard, soft, next}`; every trigger a named code with reading+threshold; consecutive state in an explicit state object (never mutated) — hence the 5th parameter and `next` in the return; documented in README |
| Samplers/parsers | guard.mjs | `/proc/meminfo`, `/proc/pressure/{memory,cpu}`, `/proc/vmstat` `oom_kill`, `/proc/loadavg`, `statfs('/')`, bounded 256 KiB tail of `~/.pi-web-ui/metrics/health-metrics.jsonl`, `systemctl show pi-web-ui.service -p MainPID --value`, `GET /api/v1/health` over the unix socket with bearer token (3 s timeout, token never logged) |
| Hard path | `runOnce` | list `^<prefix>` units (prefix validated `/^e2a-/` at startup, re-filtered in code), `stop` each, 10 s grace, `is-active` again, `kill --signal=SIGKILL` survivors; `pi-orch cleanup <id> --owner <o> [--lease <l>]` per owned-sessions line; `HOST-GUARD-TRIPPED` written **before** the notify (brief order; notify result patched in after); acts once per arm, re-armed only by restarting the unit |
| Soft path | `runOnce` | `HOST-GUARD-SOFT` + one notification per episode; cleared (renamed `HOST-GUARD-SOFT.cleared-<time>`) after 6 consecutive clean samples; a hard-tripping sample supersedes soft; nothing soft acts after a hard trip |
| Baseline | `main()` | first complete reading (6 tries, refuses to arm incomplete) → `baseline.json`; re-baselined only by the consumed `rebaseline` flag file (old/new logged) |
| Loop | `main()` | fixed 5 s interval (`--interval`), per-sample wall duration recorded, samples.jsonl rotates at 20 MB keeping one old file, flag files re-read every cycle, `disarm` = evaluate+log loudly, act on nothing |
| Launchers | `start-guard.sh`, `stop-guard.sh` | systemd unit `e2-host-guard`, MemoryMax 256M, OOMScoreAdjust −900, CPUWeight 200, RuntimeMaxSec arg (default 172800), placement env stripped; guard's name starts `e2-`, never `e2a-`, so it can never stop itself |

Fail-closed rule (brief: unreadable inputs are explicit, never read as fine): an unreadable **hard** input (`meminfo`, `vmstat`, `memory-psi`, `statvfs`, `metrics`, `mainpid`) is itself a hard code `input-unreadable:<name>` and trips. `/health` is the deliberate exception: a failed health read feeds the ×2 streak instead. Soft-only inputs (`cpu-psi`, `loadavg`) report on the soft list. `/proc/pressure` absent → hard `input-unreadable:memory-psi` + soft `input-unreadable:cpu-psi` (documented decision; PSI exists on this host). A readable-but-empty/torn metrics tail is a visibly-null row, not an error; lag streak unchanged.

## Blind spots

1. A 5 s interval cannot see a spike that appears and disappears entirely between samples; counters (`oom_kill`, metrics rows) are sticky, so those fire late but not never.
2. `lag-p99` needs two **new** A2 rows; with the ~30 s metrics cadence the minimum detection latency is ~60–65 s. Inherent to the source data.
3. The guard dies with the host — nothing monitors the monitor.
4. Once-per-arm latch: a second, different fault while tripped is sampled and logged but not acted on until the unit is restarted.
5. Fail-closed input rule cuts both ways: a single unreadable hard input (e.g. a metrics rotation window, or `systemctl` failing) trips and stops all e2a units; the parent reads the cause and re-arms by restarting.
6. During the hard path the loop blocks ~10 s (the grace design); the overrun is logged and sampling resumes.
7. The unit sweep only stops systemd units matching the prefix; an e2a process living outside any `e2a-*` unit is covered only via `pi-orch cleanup` of owned sessions — the owned file must be kept complete (common brief rule).
8. `/health` wall latency is 200–500 ms when production is busy; the 3 s timeout feeds the ×2 streak under extreme load — by design, but it means a loaded production can trip the guard on health alone.
9. Rebaseline is implemented and integration-tested with a fake systemctl, but was not exercised in a live arm (no production restart happened in this lane; restarts are the parent's).

### Item 1 [blocker] — hard path keeps stopping until verified

New semantics replace once-per-arm: the trip latches TRIPPED (written once with the cause; every attempt appended to `HOST-GUARD-TRIPPED.log`), and **every sample until re-arm** (unit restart) runs `hardSweep`: list `e2a-*` units → `stop` any unit not verified inactive → after the grace, SIGKILL any unit still not verified inactive. `list-units` failure/timeout is retried next sample (never "no units"). `is-active` only verifies on exit 3 (inactive/failed) or 4 (no such unit); timeout, spawn error, exit 2, active/activating/reloading all count as **possibly active** → stop/kill. Cleanups: all sessions on the trip sample, then retries of failures only, bounded at 5 attempts per session. Notifications: HARD at the trip; `stop incomplete: <units>` once if still unverified after 60 s; `stop verified` once when every listed unit is inactive and cleanups are done (exhausted-but-failing cleanups count as done, failures visible in the log).
- Code: `guard.mjs:482` (`hardSweep`), `guard.mjs:474` (`isVerifiedInactive`), `guard.mjs:437` (`cleanupOwnedSessions` attempts bound), `guard.mjs:~700` (runOnce trip block writing TRIPPED before notify, patching first-sweep results after).
- Tests (RED first: 6/10 stop-path tests failed pre-fix): `tests/stop-path.test.mjs` — `list-units failure is retried on later samples, never treated as "no units"`, `indeterminate is-active (timeout or exit 2) counts as possibly active → stop, then SIGKILL`, `sweep: a unit that starts while TRIPPED is stopped on the next sample`, `failed cleanup retried on later samples, bounded at 5 attempts per session`, `sweep: incomplete note once while unverified past the window; verified note once when clean; no more after`, plus the rewritten full-flow test (`hard trip: sweep stops only ^e2a- units …`).

### Item 3 [major] — bounded, consistent missing-data policy (fixes parent P1)

Every input (hard ones `meminfo, vmstat, memory-psi, statvfs, metrics, mainpid`; soft-only `cpu-psi, loadavg` treated the same on the soft side) trips `input-unreadable:<name>` only after **2 consecutive** unreadable samples (per-input streak in the evaluate state, reset on a good read; one bad read is recorded, never acted on). Metrics: the sampler keeps the **last good row with its age**; a missing file **with a present `.1` generation is a rotation window** (not an error, per parent-verify P1); missing file without `.1`, empty file, torn tail, unparseable line, and a row missing `atMs`/`lagP99Ms`/`toolsSliceOomKills` are all **unreadable this sample** — no silent `row:null` success, no coercion to 0. Staleness: last good row older than **180 s** while `/health` is OK → SOFT `metrics-stale`; older than **600 s** → HARD `metrics-stale` (thresholds `hard.metricsStaleSec=600`, `soft.metricsStaleSec=180` overridable). `mainpid`: a `systemctl show` timeout is an unreadable sample (2-streak), never a MainPID change. An unreadable-metrics sample skips the lag/tools-oom triggers entirely (no false advance or reset).
- Code: `guard.mjs:79` (2-streak policy in `evaluate`), `guard.mjs:186` (staleness), `guard.mjs:312-313` (`readMetricsTail` rotating + strict validation), `gatherReadings` last-good-row holder and `showMainPID` timeout parameter.
- Tests (RED first: 10 failures across the two files pre-fix): `tests/evaluate.test.mjs` — `unreadable hard input trips only after 2 consecutive samples; a good read resets`, `unreadable soft-only input reports on the soft list after 2 consecutive, never hard`, `a metrics-unreadable sample skips lag and tools-oom evaluation entirely`, `metrics staleness: soft at 180 s (only while health is OK), hard at 600 s`; `tests/missing-data.test.mjs` — `rotation sequence: absent (rotating) → empty → new row: never trips, streak ends clean`, `truncate of a good file …`, `readMetricsTail: a row missing a required field is unreadable this sample — never coerced to 0`, `mainpid: one show timeout … two consecutive trips`, `metrics staleness through the sampler …`; `tests/parse.test.mjs` torn/empty-file tests updated to the amended semantics.
